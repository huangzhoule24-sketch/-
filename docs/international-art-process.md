# 三地合作食肆：美术与文化内容制作

本轮依据已确认的三地综合策划，把地方空间、角色、餐点和实际经营放在同一个模块中。以下“生成要求”是制作方法的整理，不冒充历史提示词逐字记录。

## 资源组织

`assets/art/International/`保存11张生成母图，原文件不覆盖重绘。SHA、尺寸及生成输出对应记录见[international-art-manifest.json](international-art-manifest.json)。Godot通过`international_art.gd`的AtlasTexture区域读取图集。

| 资源 | 生成要求与接入方式 |
| --- | --- |
| 三地角色图，各1张 | 五列固定角色顺序；上排水墨全身立绘，下排同一人物像素形象；轮廓、配色和特征一致，脸及身体留在独立单元内。实际分行高度根据输出分别配置，避免机械均分裁掉头像。 |
| 菜品图，1张 | 五列三行；印度、北欧、希腊各一行；器皿与可见配料辅助辨认，不给图上生成文字。 |
| 三地餐馆，各1张 | 左侧完整外立面、右侧剖顶室内；地面留给真实桌席、伙伴和顾客，店外装饰不参与室内镜头全景计算。 |
| 三地行走图，各1张 | 每个角色一行、六列；向前及向后各三帧，固定基线、人物不跨格；按游戏时钟取帧，暂停时冻结。 |
| 家具图，1张 | 五列三行；各地小桌、共享桌、椅及装饰储物件；桌席布局预览后确认，经营状态变化与家具显示对应。 |

印度空间选择卡纳塔克沿海红瓦长檐与廊道，北欧空间选择伯根港湾木屋与门斗，希腊空间选择基克拉泽斯院落、蓝白墙面和炉庭。它们是具体参考下的游戏原创餐馆，不能代表整个国家的全部建筑传统。菜单跨地区时另列食物来源，不把丹麦、瑞典、挪威写成同一地方。

## 角色和文化写作

每地5位伙伴、5道菜。先确定原型、可辨识的形貌、餐馆中的性情和职责，再撰写“餐馆中的相遇—文化来历—饮食与待客”三个阅读段落。出处信息按需展开，玩家正文以人物与食物为中心。

迦楼罗、赫斯提亚等具名神话人物，与原创那伽、夜叉、宁芙个体分别说明。拉特托斯克、布洛克、斯卡蒂参考古诺尔斯文学；尼斯、胡尔德拉另列民俗背景。阿拉克涅主要传世文本标明奥维德《变形记》第六卷，不能一概写成希腊原典。现代菜品沿革与配方参考不改写成神话时代的菜单。

项目中英文小传为新写的文学转述；没有捏造古文引号。文末书目是研究参考，不能声称已逐条在线核验或经过当地读者审订。角色能力、餐馆合作、费用与时间为游戏设定；文化资料与现实烹饪指南分开。

## 从文字到实际玩法

- 印度：发酵及香料准备、低辣与无乳要求、适配餐点或换单；能力影响真实备料时间和成本。
- 北欧：天气影响采购到货；核实消息、加急和储备分别消耗时间或费用，短菜单与预约减少过度承诺。
- 希腊：烤炉批次、共享份与独立餐盘；实际份数改变存货耗用和交接时长，桌席方案影响接待容量。

三地都采用相同可追踪的基本链条：付筹备费→采购形成存货→备料→核对需求→完成交付→收款与结转成本→按真实接待解锁伙伴/配方→收到对应回信。文化阅读允许提前打开，阅读不会凭空增加收入或经营成绩。

## 可复用的AI协作方法

1. 给图像任务规定角色顺序、格数、透明背景、脸和身体留白、行走基线；收到图片后按实际输出检查格线，不能直接假设完美对齐。
2. 写作前分开记录文献事实、后世民俗和游戏原创；文学表达完成后再核对专名、时代、食材和地域。
3. 修改反馈指出具体位置与可观察的结果，例如“头像被裁掉”“新学配方尚未准备就不断被点单”“地图拖动被列表滚动抢走”。
4. 验证文字是否进入动作：菜单声明应能阻止不适配餐点交付；承诺应产生真实订单记录；回信应引用实际结果。
5. 自动化检查和人工视觉检查结合，并标注浏览器模拟与实体手机实测的区别。
