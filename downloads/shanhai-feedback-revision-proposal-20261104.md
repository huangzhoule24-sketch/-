# 《山海食肆物语》体验反馈修改意见稿

版本：2026年11月4日 · 策划讨论稿

本稿基于已修复手机物品栏返回问题的现有版本。以下新增内容均为修改建议，尚未加入游戏；同时交付的源码保持现有实现。

## 一、修改方向：让山海特点成为经营方法

作品已经建立了餐厅经营、山海伙伴、双语文化阅读和手机网页体验的基础。下一轮最值得投入的地方，是让玩家更容易看见并亲自使用这些设计：因为某位异兽、某种技法、某位远客的到来，经营安排真的发生变化。

建议以这句话作为下一轮的设计目标：

**在一家接待山海旅人的餐厅里，理解伙伴的特点，掌握不同风味，并与来自不同生活背景的食客共同决定这一桌饭怎样呈现。**

八大菜系提供饮食技法与成长路线，异兽特点提供经营条件与解决办法，本土化经营提供跨文化理解与协商的情境。三个方向应相互作用，形成一条玩家能经历的过程。

评价原创性时，可以持续使用“替换检验”：如果更换角色名字和图像，工作安排、事件选择与后果依然完全相同，这项设计还需要继续深化。每一阶段至少安排一个需要使用角色特点才能理解的经营情境。

## 二、先辨认已有内容，再决定怎样扩展

| 反馈方向 | 当前基础 | 建议修改重点 |
| --- | --- | --- |
| UI与返回 | 已有手机竖屏、五个底部入口、管理页面；最新修复增加物品栏固定返回 | 统一页面层级、返回语义和信息优先级，继续实机检查 |
| 剧情与文化引导 | 已有主线目标、来信、山海驿路、伙伴与菜品读本 | 增强开场、熟人来访与持续回访，让玩家主动发现已有文化设计 |
| 山海特色玩法 | 已有毕方炉边宴、当康丰收分配、Lin点餐等情境 | 增强现场反馈、不同解决方式和后续影响，降低稀有角色获取对体验的阻挡 |
| 外卖 | 已有真实制作、配送、费用和到账流程 | 补足路线、保温、装盒、客人需求及角色分工的可见选择 |
| 宴会 | 已有具体角色宴席与节日/经营事件 | 整理为可预约、可筹备、可复盘的经营支线 |
| 分店与本土化 | 已有分店、派驻、中央厨房、调拨及主题菜单 | 引入当地伙伴、供应条件、点餐解释和共同研发 |
| 菜系成长 | 已有研发、菜品、原料、岗位与设备基础 | 增加八大菜系与技法之间的结构化联系 |
| 美术与技术 | 已有像素场景/小人、水墨员工立绘与动作 | 统一精细度、加强空间关系，以真实设备回归检查支撑后续扩展 |

玩家没有感受到某项功能，也可能说明它出现得较晚、入口不明显，或结果缺少可见反馈。修改时应同时考虑功能本身与玩家发现它的方式。

## 三、UI与引导：让玩家随时知道自己在做什么

### 1. 重新分配界面信息的优先级

手机主界面优先保留营业时间、现金、暂停、当前任务与常用入口。负债、培训、施工和库存等详细信息可以进入统一的经营概览，但出现欠款到期、缺料、施工完成时应在主界面给出清楚提示。

普通管理页面采用一致结构：页面标题、返回上一级、关闭或返回餐厅、滚动内容。打开物品详情后，“返回”回到物品栏；“返回餐厅”直接回到经营场景。必要的经营确认应说明为何需要处理，以及目前可选的操作。

中文正文以清晰阅读为先，像素味集中于标题、边框和图标。建议正文从约16 CSS像素的可读尺寸开始验证，按钮保持足够的触摸面积。颜色同时配合文字、图标或形状，不单独承担警告含义。

### 2. 增加三层引导

- 开局引导：帮助玩家完成首次接待和收入，少量步骤即可。
- 情境引导：出现第一张特殊订单、第一场宴会、第一次缺料时，解释眼前的问题。
- 发现引导：在已有角色特征、菜牌、来信附近提供简短提示，邀请玩家进一步了解。

引导应允许回看。普通说明可稍后阅读，完成经营不以背诵典籍或答对文化题为前提。尽量不在同一时刻叠加多个气泡、任务卡和事件窗口。

### 3. 验收关注点

首次玩家能找到暂停、菜单和返回；手机上无需猜测隐藏按钮；连续进入物品、详情、员工等页面后能回到餐厅。检查开局教程、长列表、英文文本、屏幕旋转和浏览器工具栏高度变化。

## 四、剧情与文化引导：先遇见角色，再认识它的来历

### 1. 增加一个可跳过、可回看的开场

建议用约60—90秒呈现接手小馆的原因、熟人关系和第一件要办的事。对白中保留轻松的餐厅生活，让玩家先对人物产生兴趣。

白泽可以沿用已有的熟人/引路人身份，帮助整理旧店；一位山海访客带来食材或邀请，而现有员工负责第一次接待。重要角色可以先以访客或临时合作伙伴出现，让玩家在未招募到稀有员工时也能认识它。正式入职和长期能力仍沿用招聘、培养与排班规则。

开场样例方向：

> 开门那天，柜台上的旧账本还压着一张泛黄的菜单。白泽替你扶正门匾，说等会儿有位老朋友送粮来。话音未落，门外先响起了那位客人自己的名字。你让人收拾一张桌子，也第一次发现：来这里吃饭的客人，各有各的山川和脾气。

此段是拟议的游戏情境，不作为古籍原文或已经完成的剧情记录。

### 2. 用三条已有内容构成持续的故事

**当康：丰收之后，怎样安排这一批粮。** 保留采购、留现、赠粮和留用的经营选择，补上到货、仓储、邻里领取以及后续来信的现场表现。不同选择都应有合理收益与代价，让玩家真正权衡现金、损耗、人情与后续需求。

**毕方：一只脚，也能守住一炉火。** 延展已有炉边宴，让独足形貌、灶台安排、火候控制和团队接力在画面上发生联系。筹备时的安排影响出餐节奏和宴后评价，人物特点进入工作的具体过程。

**Lin：读懂一个菜名，也要吃到适合自己的一餐。** 延续菜名、用料与待核实事项的说明，增加一次交流后的回访。玩家可以看到客人如何理解、提出建议，以及餐厅怎样兑现承诺。

### 3. 建立“山海手账”的发现路径

建议将已有图鉴、驿路和来信组织为“遇见—一起做事—留下记录—再次相逢”的阅读线索。初次只展示一段鲜明的人物介绍，完成相关情境后再展开更丰富的身世、原文和出处。

典籍来源分开登记，《山海经》《搜神记》等不混标。玩家正文保持自然的文学表达，考据、古注与游戏创作的关系放入可展开的来源页。英文阅读解释陌生意象，引用译文继续保留译者和来源信息。

## 五、八大菜系与后厨成长：从做会一道菜，到形成一家店的风味

### 1. 建立两条相连的线索

八大菜系体现后世地域饮食传统，山海谱系体现神话地理、形貌与文化意象。两者可以在游戏中相遇，但不宜将某只异兽直接等同于某个现代省份，也不把八大菜系说成《山海经》已有的分类。

建议的成长结构：

**家常基础 → 蒸、煮、炒、炸等技法 → 设备与备料能力 → 地域风味分支 → 主题菜单与宴席。**

研发可以使用现有厨师培养、食材试作和设备条件。先把几条关系做清楚，再考虑增加新的点数或货币。

### 2. 八个分支的设计方向

下列是玩法切入口，后续菜品选取应结合可靠资料和地区经验校订，不用一个标签概括整套菜系。

| 菜系 | 可优先研究的技法与食材关系 | 可转化的经营选择 |
| --- | --- | --- |
| 川菜 | 多味型、复合调味、炒制与煨炖 | 备料组合、不同味型菜单、复杂工序的人员安排 |
| 粤菜 | 鲜度、蒸制、煲制与点心工序 | 到货安排、蒸位容量、分时出餐 |
| 鲁菜 | 汤、火功、海产与主料处理 | 高汤准备、火候稳定、原料利用 |
| 苏菜 | 刀工、炖焖与细致成形 | 备菜工时、成菜完整度、宴席节奏 |
| 浙菜 | 时令、鲜嫩与不同地域风味 | 随季节采购、短时间出餐、菜单轮换 |
| 闽菜 | 海味、汤与地方发酵调味 | 汤底筹备、储存条件、味道解释 |
| 湘菜 | 鲜辣、酸味、腌腊与蒸炒 | 鲜料与储备搭配、备菜周期、菜单互补 |
| 徽菜 | 山野物产、炖烧与保存方式 | 季节储备、慢工序产能、特色食材供应 |

首轮建议只制作两条可体验的样例，如川菜与粤菜分支，各选少量代表菜。川菜样例应展示麻辣以外的味型层次；粤菜样例也不能被简化为统一的“清淡”。

现有25道菜应逐道评估并保留有价值的内容：部分作为基础菜，部分进入技法或地域分支，部分保留为山海主题创作。无需为了凑菜系数量而一次重做整份菜单。

### 3. 让不同技法影响后厨

蒸制考虑蒸位和时间，煮制考虑汤底与并行照料，炸制考虑油温和批次，炒制考虑备料和即时火候。设备、员工与空间因此产生不同安排，玩家能通过队列、烟汽和出餐节奏看见区别。

## 六、操作台玩法：增加短时试作，并继续支持自动经营

建议增加可选的“厨艺试作”，每轮约20—40秒，用来认识一道菜的关键工序。主店日常营业继续由员工自动完成，玩家可在试作、活动或宴会前的关键准备中参与。

煎饼果子样例可围绕摊面、加配料、控制翻折时机展开；炒菜样例突出下料顺序与火候窗口；蒸、煮、炸分别有对应的视觉和操作反馈。

试作成果可以记录为配方调整、一次宴席的准备方案或人物对话。自动训练也应能够学习这些做法，行动与操作能力不同的玩家都能推进。手动成绩的奖励要有限，防止反复操作成为维持收益的必需劳动。

火焰、蒸汽、油花和锅铲动作应与真实工序状态同步：开火后才有火焰，出锅时才进入装盘动作；暂停与低性能模式下依然清楚可读，特效不遮挡角色和按钮。

## 七、外卖、宴会与守店事件：优先深化，再决定扩张

### 1. 外卖：把当前已有的制作与配送过程做得可判断

在已有订单、费用和实际送达到账的基础上，增加天气/路线、保温、分装和交付时间的选择。不同菜品适合不同包装或路线，顾客的要求应在接单前明确展示。

异兽特点可以成为特定情境的解决条件，但需要研究并说明其依据与游戏创作：飞行伙伴能够探索特殊路线，同时考虑风雨、岗位离岗和体力。这样的人物安排应有真实代价和反馈。

### 2. 宴会：形成“筹备—开席—复盘”

预约时看到人数、主题与用餐需要；筹备时选菜、布置席位、排班和安排备料；开席时观察上菜顺序和客人反应；宴后收到评价、账目及人物回信。

优先沿用毕方炉边宴做一个完整样例，再扩展邻里宴、山海来客宴或交流宴。菜系、人物特点和团队能力共同决定方案，宴后反馈明确对应本次实际选择。

### 3. “霸王餐”建议发展为可选择处理方式的守店事件

先区分恶意逃单、支付故障与点餐误会。普通纠纷有核对、协商和重新安排等处理方式；确认恶意后，可选择追讨或驱离。

若增加战斗，可用一段短小、非血腥的异兽守店对决呈现，围绕能力搭配和场景互动展开，支持自动处理。奖励、损失与后续回访应能解释，不额外建立一套庞大的装备、刷怪和强制反应操作系统。

建议先做一个完整事件，测试它是否提升餐厅故事的趣味，再决定是否扩大。角色能力的游戏表现也应保留与来源的对应说明。

## 八、跨国餐饮本土化：让当地人参与这家店怎样经营

建议在现有分店系统上试做一个海外或跨文化街区分店。以具体城市、社区和人物展开，顾客偏好由个人经历、饮食需要与用餐情境决定。

| 本土化方向 | 建议设计 | 玩家需要作出的选择 |
| --- | --- | --- |
| 员工 | 当地前厅、厨师或供应伙伴与山海员工协作 | 谁负责解释菜名、回应需求和共同研发；培训需要哪些时间 |
| 菜品 | 保留招牌菜，同时研发明确标注的当地协作版本 | 哪些风味可调、哪些原料可替换、菜名和用料如何说明 |
| 装修 | 保留山海锚点，结合当地空间使用与审美 | 桌位、动线、灯光、展示与文化阅读位置如何安排 |
| 服务 | 菜牌说明、份量、用餐时间、饮食限制和反馈方式 | 怎样确认承诺、记录反馈与改善接待 |
| 供应与账目 | 利用现有采购、调拨和分店会计基础 | 原料成本、损耗、售价与出餐能力怎样平衡 |

可以设置一次协作菜单：当地厨师提出家乡的一种做法，山海伙伴提供另一种处理方法，玩家选择试作并邀请双方食客反馈。菜单记录本次共同创作的名字与故事，让传播包含交流的回应。

评价应同时考虑经营表现、服务承诺是否兑现、团队协作与食客是否理解这道菜。不要设置笼统的“文化纯度分数”，也不要把所有外国顾客设为同一种口味。

## 九、美术精细度与餐厅空间

### 1. 保留已有风格方向，提升统一程度

员工立绘继续采用美型、较高拟人程度的水墨表达；场景、UI、物品和场景小人继续采用传统像素风。精细化可以从轮廓、服饰层次、材质、配色和动作衔接入手。

每位角色先确认2—3个稳定锚点，如角、翼、尾、独足或具有辨识度的纹样；立绘、像素小人和职业动作共同保留这些特征。主次角色的精细度应接近，避免一张立绘很完整而同角色小人缺乏识别度。

### 2. 优先重整餐厅布局

让前厅、后厨、传菜区、收银与庭院在视觉上易分辨，同时保留顺畅的工作路径。桌椅朝向、桌面高度、人物坐姿与手部位置统一校对；职业动作依附真实设施，设备在制作、空闲和维护时有对应状态。

像素光影可突出灶火、灯笼和不同时段的气氛。装饰层次服务于空间识别，中文正文、角色面部和关键操作保持清晰。

### 3. 建立资源检查清单

继续遵守既有动作要求：行走起伏小、脚部不交叉抽动，飞行/爬行/步行各有动作逻辑；坐下和工作有明确锚点；面部及上半身进入头像框；前景遮挡与角色层级保持稳定。低性能模式优先减少装饰特效，保留经营状态的必要反馈。

## 十、技术修复与实施优先级

### P0：先保证能顺畅完成一次营业

- 回归物品栏及其他管理页的返回、关闭、重复进入、横竖屏切换。
- 检查长列表、引导窗口、英文文本与不同手机工具栏下的可见范围。
- 检查顾客/员工重叠、桌椅锚点、装修撤销、设备交互及镜头操作。
- 检查暂停/继续后的音乐、存档读取、升级旧档和网页缓存更新。
- 收集设备、浏览器、操作步骤、实际结果及截图，让每个bug可以复现。

### P1：制作一个能体现特色的完整体验段

建议范围：一个开场、三位重点角色的持续关系、两条菜系小分支、一场增强宴会、一个可选厨艺试作，以及一条“做事后发现文化”的手账线索。

这一阶段先复用已有毕方、当康和Lin内容，集中提高玩家能看见、能选择、能复述的程度。

### P2：进行小规模验证后扩展

增加一个跨文化分店试点，深化外卖路线，试做一则守店事件；逐步扩充菜系和角色能力。每次扩展都检查是否确实带来了新的经营选择，以及玩家能否理解。

## 十一、下一轮可采用的验收问题

| 目标 | 可观察的验证方式 |
| --- | --- |
| UI更清楚 | 让首次玩家独立打开管理页、查看详情并回到餐厅，记录误触和求助点 |
| 山海特色可感知 | 体验后请玩家说出一位角色的特征，以及它怎样影响了经营安排 |
| 菜系成长有意义 | 让玩家解释为什么选择一条研发路线，以及设备/工时如何随之变化 |
| 自动经营节奏保留 | 不玩手动试作也能推进；试作用户与自动经营用户都能理解结果 |
| 文化介绍有效 | 让玩家用自己的话介绍一个角色或菜名，并能找到进一步阅读的入口 |
| 跨文化理解 | 邀请不同文化背景的体验者判断菜牌是否易懂，能否提出需要并看见回应 |
| 本土化产生选择 | 玩家能指出一次菜单、员工或空间调整及其成本和效果 |
| 美术更统一 | 对照同一角色的立绘、小人、动作与图鉴截图，检查锚点和材质一致性 |
| 技术更稳定 | 使用真实设备复现此前问题并记录更新前后的结果，区分模拟检查与真机试玩 |

此阶段的核心交付可以是一段约15—20分钟、具备开场、选择、经营后果与回访的体验流程。先用这一段证明作品的特色，再扩充规模。
