# 山海食肆物语 · 座位与招聘修订版

SH-WEB-BRANCH-R2，电脑与手机浏览器共用版本。

## 顾客坐姿

三地餐桌按各自椅面逐一校准。入座点单、候餐、送餐等待和用餐都使用固定座位及坐姿；走到座位的路线与椅面上的显示位置分别处理。普通桌人物与椅面重合，共享桌后排下半身由桌沿遮挡。平移、缩放、暂停不会把候餐顾客移到过道。原有存档的候餐顾客会直接使用修正后的座位，无需重开。

## 当地招聘与员工

- 开业团队直接包含一位当地厨师和前厅员工，已包含在原合作筹备费中。旧档缺少开业厨师时补齐，不重复收费。
- 所有当地候选从开店起即可招聘，取消人物的结账单数/结缘门槛。菜谱原有成长条件继续保留。
- 当前店底部“招聘”进入独立招聘页，“员工”进入已录用员工和排班页。
- 参考主店基础招聘价格：普通招聘200资金，或5灵石；可直接选择候选。招聘价格读取原平衡配置。当地角色有明确岗位、技能与文化简介，录用后有空位则自动当班，满员则进入候补。
- 当班名额跟随主店成长，开局3位、当地最多5位；可安排候补、当班与培训。基础班组会在缺员或培训时补岗，避免营业因缺少命名厨师而卡死。
- 旧档已安排过的当地员工保留录用资格；新录用、支付方式、排班与培训均保存。

## 进入场景

完成白泽六步引导 → 更多/场景 → 跨国食肆 → 支付游戏内筹备费（印度350、北欧400、希腊450）→ 进入此店场景。已开店不重复支付；主界面“场景”可回主店或切换其他已开店铺。保留主店、三地菜单/图鉴/来信、手机竖屏、拖动缩放、返回与音乐功能。

## 本地运行及更新 WorkBuddy

资源包已包含全部资源。解压后Windows双击Start-Web.cmd（需Python3）；其他系统运行 `python prepare-site.py --launch`。学生访问已部署网站只需浏览器。

更新原WorkBuddy应用：上传本包，发送包内“给WorkBuddy的更新指令.txt”。在实际发布目录执行 `python prepare-site.py --site-root <原网站根目录>`，脚本核对旧版本、在网站外备份、失败回滚并保留自定义首页。然后重新部署原应用，沿用原域名，不清除浏览器网站数据。新建静态网站则先运行 `python prepare-site.py`，仅发布生成site目录的内部内容。

源码包另提供，使用Godot4.6.3导入project.godot；不能直接当作WorkBuddy静态网站部署。浏览器手动保存后需等待后台写入，再刷新或关闭页面。
