# 山海食肆物语 · 主店法务合并版

SH-WEB-LEGAL-R1 / SH-SOURCE-LEGAL-R1，Godot 4.6.3。

## 合并依据

以已交付的SH-WEB-BRANCH-R2为基础，合入用户上传的v1.9.6文本源码。上传资料实际还包含行政、税务与刑事风险的后续代码，本版将这些已提供内容一并接入。未用较旧整套界面、文化、美术、声音或导出设置覆盖当前版本，也未升级引擎。

依据用户最新要求，**法务系统暂时只添加在主场景**。三个跨国场景保留原经营、角色、菜品、招聘、座位和移动缩放机制。

## 入口与内容

- 主店“更多 → 法务与合规 → 法务”：保洁度、低保洁度状态、提示牌、案件记录、赔偿与罚款结清。
- 主店“更多 → 行政与公关”，或点击主店门外的税吏：周期摊派、检查概率、税务、风险与查封状态。
- “经营状态”可查看主店保洁摘要，并进入法务页面。跨国店不出现新增法务入口及低保洁度徽章，不能直接执行当地行政打点。
- 新增界面文案和事件反馈有英文对应，保持原有语言切换方式。

## 民事规则

安全提示牌沿用原装修流程，阶段1起可购买，资金120、工期30游戏分钟，需负责人；未完工不生效。原有素材和缺图回退继续可用，不需要额外美术包。

保洁度初始100。第14天起每日衰减3；卫生检查失败扣15、通过加10；完成后厨清洁加30。第14天起连续失败达到门槛会获得低保洁度，恢复至70可提前解除。

低保洁度期间可遇到店内湿滑、食品安全两个民事事件。私下赔付与法庭选项保留上传源码的配置。湿滑案按是否有完工提示牌判定；食品安全案按当前保洁度是否达到60判定；赔偿不足会计入待付。上述判据为架空游戏简化规则，不是现实案件责任判断。

## 行政与刑事风险

主店场景第7天起每7天可遇到摊派。打点500、持续7天，并增加风险25；拒绝降低风险15。税吏犒劳300，主店税务豁免14天，风险增加20；有效期内不可重复购买。

主店堂食按上传配置计取5%的游戏营业税：销售仍全额入账，税款单列费用和资金流水。跨国食肆、旧分店与外卖沿用合并前税务处理，不应用新增税率。共同资金、总账和声望仍是原游戏的共享数据，并未另造四套资金存档。

风险达到100触发主店刑事事件：按配置抄没现金、声望清零、取消原打点和免税，主店查封7游戏日。

**为符合“只在主场景”的要求，查封不再直接跳过整个世界的7天。** 主店暂停接客，到期自动恢复；其他店继续按原时钟推进。主店房租、工钱及其他既有日结按正常流程处理，避免一次性预扣后又重复日结。取消主店在场订单时释放员工和设备，保留培训调度；未履行的Lin预收款按原有退款机制处理。

## 场景边界

新增四类事件及主店卫生检查只在主场景进入事件流程。已排队的主店法务事件在跨国场景暂缓展示，回主店后仍可处理，不阻塞当地事件与正常经营。保洁数据属于主店；跨国店不创建独立法务系统、不加税、不新增提示牌机制，也不因主店查封而停止接客。

## 存档

支持合并前Branch-R2及更旧正式存档：缺少legal/admin字段时补默认值，保留既有经营进度。上传版本已有的保洁度、打点、免税、风险、案件记录可继续读取；部分字段缺失时逐项补齐，不整块覆盖。非法数值由存档校验拒绝。

保留现有手机竖屏、设备自动路由、缩放、返回、音乐续播、跨国开业厨师与当地招聘。自由体验/破解版仍与正式经营入口和存档隔离，本版按正式经营交付。

## 使用

完整网页包：解压后Windows双击根目录Start-Web.cmd（本地启动需Python3），或运行`python prepare-site.py --launch`。静态部署先运行`python prepare-site.py`，发布生成site目录的内部内容。学生访问部署后的网页仅需浏览器。

原WorkBuddy网站更新：上传本版完整游戏包，发送包内《给WorkBuddy的更新指令.txt》，运行`python prepare-site.py --site-root <实际发布目录>`后重新部署原应用。沿用原域名，不清除浏览器网站数据。助手未操作用户WorkBuddy账号。

源码：使用Godot4.6.3导入project.godot。全部当前运行美术、字体和音频随完整源码包提供；上传的文本包不需要另补图片。旧导出工具可能依赖历史缓存，新机器可安装同版本标准导出模板。源码不是可直接发布的静态网站。

当前说明优先于`docs/imported-legal/`下的上传版历史说明，尤其是法务作用范围、引擎版本和查封时间处理。
