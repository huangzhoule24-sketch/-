## 玩家会读到什么

30位员工与25道菜全部重写；另为6位特殊来客增加小传，共61篇中英文阅读。员工每篇包含完整引入、保留的三个文学段落和一节新增典籍身世；菜品与来客各三节。全册54段典籍节选，配中文白话与英文释意。新文字不再以「典籍原貌／流传辨析／游戏改编」为统一提纲，也不再重复开发说明、配方边界和经营数值。

文化页新增「中文／English」，语言选择保存在独立用户偏好中。英文按读者的理解重新组织，而非逐字搬运中文；保留中文名、拼音，解释陌生的名物与双关。原本只显示三句摘要的页面已恢复完整正文，文化页不再混排技能数值和配料界面。

角色内容从形象与故事切入，再以食肆日常让人物可亲；菜品从滋味、手艺、餐桌与命名切入。跨文化小段落尽量提供具体理解途径：

- 凤凰的安宁意象，与其他phoenix故事形成对话。
- 应龙从雨水、农事与一顿热饭被理解，不把所有龙都套进同一种想象。
- 精卫石锅拌饭分别保留中国神话与韩国菜式的来路。
- 「云吞／wonton」「混沌／馄饨」「无面」等解释文字趣味。
- 「鲜」「汤」「仙」「真」等通过味道和语气解释，避免只有字面译名。
- 公平、照顾差异、听懂彼此等主题通过食肆相遇表达，不用国籍或性别机械规定食客偏好。

这是文化阅读模块的双语内容，不等于整个游戏界面完成了英文翻译，也不等于已经通过课程传播效果评估。

## 阅读入口与返回

员工、菜单、研发、图鉴中的原「文化简介」入口继续保留。未招募员工和未研发菜品仍可读；不会发员工、解配方、变更经济数值或消耗经营随机数。

特殊顾客图鉴在原有遇见后展示的卡片中增加「来客小传 / Story」。未遇见者不露身份，直接调用阅读入口也受到相同限制，不为文化内容绕过顾客解锁。

返回仍使用固定页头按钮，回到实际父页并恢复图鉴分页与滚动；窄屏正文自动换行，可纵向滚动。新原文节选不恢复外部浏览器链接和完整参考书目，玩家可以离线阅读。

## 文案与来源怎样维护

唯一当前编辑源为 `docs/culture-research/player-edition.json`。历史 `employees-a.json`、`employees-b.json`、`dishes.json` 及旧证据继续保留，但不再用它们覆盖后来增加的员工与新文案。

执行：

```bash
python3 tools/build_culture_catalog.py
python3 tools/verify_culture_sources.py
```

前者校验30员工、25菜品、6顾客与真实配置ID/名称，生成游戏 `config/culture.json` 和完整读本 `docs/culture-entries.md`；后者实际取回来源并核对短引。`--offline` 只重核已缓存文件，不冒充新联网。

本次实际取回35份在线文件，登记52条来源关系。包括《山海经》《神异经》《淮南子》《庄子》《搜神记》等古籍录文、公开辞典数据、当代菜式说明，并检索《随园食单》《东京梦华录》《梦粱录》《礼记正义》《齐民要术》的饮食语境。检索通过公开古籍仓库的文件索引和实际HTTPS取回进行；部分公共网站及搜索API在环境中被代理拒绝，没有将其页面或搜索摘要冒充已阅读资料。

34处玩家短引都来自本次取回的古籍电子录文，附本次撰写的英文释意。正文、古注、后世传说和食肆叙事的出处关系保存在编辑数据与研究说明中，玩家页面只保留适量的书名落款。古代神异叙事不被写成现实食疗指南；例如精卫菜中的丹粟米保持想象食材的说法，丹砂的区别保存在研究备注中。

现代材料用于了解词义和菜式，不整段复制其文案。此次仍是电子录文研究与编辑，不是古版书影校勘、全部民俗流变研究或真人文化接受度调查。
