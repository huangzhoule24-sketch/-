# 美术接入与替换说明

这套工程继续使用 Godot 4.6.3。策划 v1.3 的 Unity Animator / Resources.Load 等名称在本工程中分别对应员工动作状态、帧序列绘制和统一 `AssetCatalog` 服务，不需要迁移到 Unity。没有正式图片时使用现有程序绘制的餐厅、角色与图标，服务本身也提供中性占位纹理。

## 一、目录与加载顺序

| 用途 | 路径 | 生效方式 |
| --- | --- | --- |
| 随游戏发布的内置图片 | `res://assets/art/`，源码目录 `assets/art/` | 放入图片后通过 Godot 导入，重新导出游戏 |
| 编辑器 / 开发运行时覆盖 | `res://CustomAssets/`，源码目录 `CustomAssets/` | 启动时读取；开发者模式支持热重载 |
| 桌面导出版覆盖 | 可执行文件同级 `CustomAssets/` | 无需修改 PCK；放入图片后重新载入或开启热重载 |
| 网页版运行时覆盖 | `user://CustomAssets/` | 使用浏览器文件选择导入；不能直接扫描玩家电脑目录 |
| 默认稀有度视觉配置 | `config/rarity.json` | 修改后调用 `RarityDisplay.reload_config()` 或重启 |
| 动作与属性参数 | `config/animation.json` | 由场景与模型读取，不需要烘焙到图片中 |

同一资源 ID 的顺序是：**有效的自定义图片 → 有效的内置图片 → 中性占位纹理**。覆盖图片损坏时继续尝试内置图片。餐厅场景在没有真实图片时保留矢量绘制，因此暂时不导入美术仍能运行。

桌面导出时，应将 `CustomAssets/` 模板复制到可执行文件旁；它不需要打入 PCK。工程中 `CustomAssets/.gdignore` 阻止 Godot 将用户覆盖文件当作内置美术导入，模板目录允许为空。内置图片放在 `assets/art/`，不要把正式内置图片放进被 `.gdignore` 忽略的模板目录。导出配置应包含 `assets/art/manifest.json` 和 `config/*.json`。

统一资源 ID 是 `分类/名称`，不带扩展名。仅接受以下四个分类；目录大小写必须一致。文件名使用英文字母、数字、下划线或短横线，推荐全部小写。不得使用空格、中文文件名、子目录、绝对路径或 `..`。

| 通用餐厅背景 | `Backgrounds/restaurant` | `Backgrounds/restaurant.png` |
| 阶段背景（优先于通用背景） | `Backgrounds/restaurant_stage_1` | `Backgrounds/restaurant_stage_1.png` |
| 羬羊待机单图 | `Characters/qianyang_idle` | `Characters/qianyang_idle.png` |
| 羬羊待机第 0 帧 | `Characters/qianyang_idle_0` | `Characters/qianyang_idle_0.png` |
| 羬羊做菜第 1 帧 | `Characters/qianyang_cook_1` | `Characters/qianyang_cook_1.png` |
| 阳春面菜品图标 | `Dishes/noodles` | `Dishes/noodles.png` |
| 员工导航图标 | `UI/btn_employee` | `UI/btn_employee.png` |
| 双人桌 | `UI/decor_table_two` | `UI/decor_table_two.png` |
| 收银台 | `UI/decor_cashier` | `UI/decor_cashier.png` |
| SSR 徽章图标 | `UI/rarity_ssr` | `UI/rarity_ssr.png` |

员工 ID 以 `config/employees.json` 的 `id` 为准，例如 `qianyang`（羬羊）、`owl`（鸮）、`earmouse`（耳鼠）、`bifang`（毕方）、`nine_tailed_fox`（九尾狐）。不能用显示名称或另编的神兽 ID 替代。菜品 ID 以 `config/dishes.json` 为准，例如 `noodles`、`fried_rice`、`plum_juice`。装饰 ID 以 `config/decorations.json` 为准，场景调用时增加 `UI/decor_` 前缀。

导航图标约定使用 `UI/btn_employee`、`UI/btn_encyclopedia`、`UI/btn_system`、`UI/btn_decoration`、`UI/btn_research`、`UI/btn_more`；新界面需要增加图标时采用同样方式向 `AssetCatalog` 取图。正式资源交付时应逐一确认调用点，加入图片文件本身不会创建新按钮或新玩法。

建议背景 1920 × 1080；角色单帧 64 × 64 或 128 × 128，所有帧画布大小和脚底锚点一致；UI 图标至少 64 × 64。PNG 支持透明；JPG/JPEG 适合不透明背景。导入接口单文件上限 32 MiB、边长上限 8192、总像素上限 32 × 1024 × 1024。GIF、SVG、Godot `.tres`、`.res`、`.gd` 等文件不会作为外置美术加载。

## 三、动画帧与覆盖

员工动画命名：`角色ID_状态_帧号.png`。状态支持 `idle`、`move`、`cook`、`serve`、`clean`、`cashier`、`promote`，休息扩展使用 `rest`。服务接口接受大写开头的状态，会统一转为小写。帧号为不补零的十进制非负整数：`0`、`1`、`2`、`10`，按数字排序。

示例：先在内置目录放入 `qianyang_idle_0.png`、`qianyang_idle_1.png`、`qianyang_idle_2.png`，再在自定义目录只放 `qianyang_idle_1.png`。运行时第 1 帧采用自定义图片，第 0、2 帧保留内置图片。自定义 `qianyang_idle.png` 只替换第 0 帧；如果同时存在自定义 `_0.png`，编号第 0 帧优先。没有内置动画而只有一张自定义图时，返回一帧，移动和工作反馈仍由程序完成。

在图片上不要画死稀有度徽章、角色名字和动作进度。朝向由渲染层翻转，移动与工作速度由属性及 `config/animation.json` 控制。这样后续训练、岗位变化和数值调整不需要重做图片。

## 四、统一服务 API

实现位置：`scripts/services/asset_catalog.gd`，类型为 `RefCounted`。业务和 UI 不直接从外置目录 `ResourceLoader.load()` 图片，更不能加载外置脚本。外置 PNG/JPG 被读取为字节并解码为像素。

```gdscript
const AssetService = preload("res://scripts/services/asset_catalog.gd")
var assets = AssetService.new()

# 所有缺图调用均有安全回退，get_texture 不返回 null。
var picture: Texture2D = assets.get_texture("Dishes/noodles")
var frames: Array[Texture2D] = assets.get_frames("qianyang", "Cook")

# 保留程序绘图时，先判断是否存在真正可用的图像。
if assets.has_frames("qianyang", "Cook"):
    frames = assets.get_frames("qianyang", "Cook")
if assets.has_image("Backgrounds/restaurant"):
    picture = assets.get_texture("Backgrounds/restaurant")

# UI 将返回的图片赋给 TextureRect.texture，或在场景中 draw_texture_rect。
# changed 信号后刷新已经显示的 TextureRect / 重画场景。
assets.changed.connect(queue_redraw)
assets.developer_mode = true

func _process(delta: float) -> void:
    assets.poll(delta)
```

| 方法 / 属性 | 返回或用途 |
| --- | --- |
| `get_texture(resource_id: String)` | `Texture2D`，可为占位纹理 |
| `culture_resource_id(kind: String, entry_id: String)` | 文化专图固定资源 ID；支持 `employees` / `dishes`（兼容单数）；无效类别或 ID 返回空字符串 |
| `culture_texture(kind: String, entry_id: String)` | 简介专图 → 已有肖像/菜图 → 中性占位，返回 `Texture2D` |
| `get_frames(character_id: String, state: String)` | `Array[Texture2D]`，至少一帧 |
| `has_image(resource_id: String)` | 是否有实际有效图片；占位不算有效图片 |
| `has_frames(character_id: String, state: String)` | 任意单帧或编号帧有效则为 `true` |
| `is_placeholder(texture: Texture2D)` | 判断是否为本服务的占位纹理或 `null` |
| `get_resource_info(resource_id: String)` | 已解析 ID、可用状态、内置/自定义路径，供开发检查 |
| `reload()` | 重新扫描、清理缓存并发出 `changed` |
| `poll(delta: float)` | 开发者模式下按 `poll_interval` 检查图片和清单变化 |
| `developer_mode` | 默认 `false`，开启才自动监测修改 |
| `poll_interval` | 默认 1 秒，最低 0.1 秒 |
| `last_errors` | 损坏图片或清单的开发检查信息 |
| `import_image(bytes, relative_path)` | 校验并保存图片，返回 `{ok, error, id, path}`；失败返回 `{ok:false,error}` |

监测使用修改时间、大小和内容摘要，避免同一秒内保存同尺寸图片未被发现。仅在开发者模式扫描；图片多时可提高 `poll_interval`。`reload()` 始终允许手动刷新。`RarityDisplay.reload_config()` 是稀有度配置的单独刷新方法。

测试可以用 `AssetService.new(builtin_directory, custom_directory)` 指定临时根目录，不会写入正式素材。一般运行不传参数，服务自行选择当前平台正确的外置根目录。

## 五、资源别名清单

内置 `assets/art/manifest.json` 与外置 `CustomAssets/manifest.json` 都可配置别名。外置清单中的同名别名优先：

```json
{
  "version": 1,
  "aliases": {
    "restaurant": "Backgrounds/restaurant",
    "noodles": "Dishes/noodles",
    "qianyang_idle": "Characters/qianyang_idle"
  }
}
```

这样 `get_texture("noodles")` 等同于 `get_texture("Dishes/noodles")`。完整 ID 最明确，推荐业务代码直接使用完整 ID。没有别名时，服务也会接受四个目录中唯一的同名资源；若不同分类同时存在同名资源，则要求完整 ID 或明确别名，避免静默取错图。清单只描述别名，不执行代码，也不能指向资源目录之外。

## 六、运行时图片导入与网页文件选择

桌面 `FileDialog` 选择图片后，由界面读取文件字节，然后调用：

```gdscript
var bytes := FileAccess.get_file_as_bytes(selected_path)
var result: Dictionary = assets.import_image(bytes, "Characters/qianyang_idle_0.png")
if not result.ok:
    show_import_error(result.error)
```

`relative_path` 是用户选择的目标槽位，不是原文件的绝对路径。导入只允许四个目录的一层文件名，并拒绝目录跳转和符号链接。保存完成会立即重新载入。

浏览器的 `FileDialog` 无法直接访问用户磁盘路径，应使用 HTML `<input type="file" accept="image/png,image/jpeg">` 或 Godot `JavaScriptBridge` 触发文件选择。取得 `File.arrayBuffer()` 后，将其转成 `PackedByteArray` 传给同一个 `import_image()`。目标位置自动为 `user://CustomAssets/`。不应尝试扫描 `C:\\...` 或把网页上传界面设计成任意代码导入。网页保存是否跨会话保留依赖同源浏览器存储；无痕浏览、清理站点数据或更换站点地址会影响保留。

## 七、统一稀有度组件

`scripts/ui/rarity_display.gd` 提供静态 `color_for()`、`label_for()`、`stars_for()`、`icon_for()`、`scene_marker_for()`、`create_badge()` 和 `apply_border()`。`create_badge("SSR", false, assets)` 返回 `PanelContainer`，可以直接加到姓名旁。`apply_border(card, rarity)` 让员工卡片使用同色边框。

所有默认颜色、中文标签、星数和可选图标 ID 位于 `config/rarity.json`：N 灰 `#9E9E9E` / 普通 / 0 星，R 蓝 `#2196F3` / 稀有 / 1 星，SR 紫 `#9C27B0` / 超稀有 / 2 星，SSR 金 `#FFD700` / 传说 / 3 星。场景默认只有 SSR 显示金色星标。没有徽章图片时用文字和星号，仍可识别稀有度。

稀有度是收集与视觉分类；岗位匹配、工资和培养效果由游戏机制决定，不应在美术或文化说明中将员工的价值简化为稀有度。

## 九、导出与交付

先完成代码修改，再顺序运行以下命令，避免多个 Godot 编辑器同时导入一个工程：

```bash
bash tools/export_web.sh
bash tools/export_windows.sh
python3 tools/package_release.py
python3 tools/serve_web.py --port 8000
```

产物目录为 `build/full-web/`、`build/full-windows/`；ZIP 为 `build/山海食肆物语-v1.3-Web.zip`、`build/山海食肆物语-v1.3-Windows.zip`、`build/山海食肆物语-v1.3-Source.zip`。源码包保留可编辑的 GDScript、配置、场景、图片路径模板、开发文档、测试和工具，排除 Git 历史、Godot 缓存、旧下载构建与常见密钥文件。

每次导出记录游戏源文件 SHA-256 指纹；打包会检查两个平台对应同一份源码并校验导出文件，拒绝把旧 PCK 与新源码混为同一版。`build/v1.3-artifact-manifest.json` 记录源指纹、大小与各 ZIP 校验值；`build/v1.3-SHA256SUMS.txt` 可用于下载后核对。文档和测试更新只需重新打包；游戏脚本、配置、内置素材或导出配置更新后需要重导出。结构检查与 Linux 上读取 PCK 不等于 Windows 本机试玩，交付验证应分别记录。


## 十、文化简介专图与全部固定槽位

文化简介为每位员工、每道菜保留独立展示图片，不要求替换游戏中的动作帧或菜单缩略图。共51个槽位：26位员工、23道标准菜及2道原创隐藏菜。路径表与 `CustomAssets/manifest.json` 的 `culture_slots` 数组一致；加入图片无需修改文化正文，也不会影响战斗、经营或员工数值。

调用方式：

```gdscript
var resource_id: String = assets.culture_resource_id("employees", "qianyang")
# Characters/qianyang_lore
var picture: Texture2D = assets.culture_texture("employees", "qianyang")
var has_picture: bool = not assets.is_placeholder(picture)
var dish_picture: Texture2D = assets.culture_texture("dishes", "baize_hidden_banquet")
```

加载顺序为：**有效自定义专图 → 有效内置专图 → 现有角色待机图/肖像或普通菜图 → 中性占位**。角色待机图支持 `get_frames()` 已有编号规则，缺少专图时选首张可用待机帧，再尝试旧版 `Characters/<员工ID>` 肖像。专图与动作帧、菜图互不覆盖；可以只交付部分图片，其余简介仍能阅读。专图不要以 `<员工ID>_idle` 命名，以免改动餐厅里的角色。

下表路径均相对于桌面 `CustomAssets/` 或内置 `assets/art/`。内置图片需重新导出；外置图片可热重载；网页通过原图片导入入口保存到 `user://CustomAssets/`。表中 PNG 可改为 JPG/JPEG，透明插图推荐 PNG。建议简介图使用清楚主体、留白合适的方形或横幅画布，例如960×720；界面按比例完整显示，不应把正文或来源信息画死在图片里。

后续补入图片时另行记录作品来源、作者与使用许可；文化文字中的典籍出处不自动授予现代插画的使用权。本轮未抓取或生成正式美术。
